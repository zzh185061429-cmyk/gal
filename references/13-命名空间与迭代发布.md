# 命名空间与迭代发布

> 给"要长期维护、或要发给别人用"的项目。参照项目用 `mirage` 前缀躲过的坑，这里制度化。

## 1. 命名空间规范

你的项目所有**逃出 iframe 的名字**都要带项目前缀（下表以 `<pfx>` 代指，如 `galX`）：

| 对象 | 规范 | 撞名的后果 |
|---|---|---|
| 自定义刷新事件 | `<pfx>_story_updated` | 两个前端互相触发重解析、连环刷新 |
| 聊天变量 key | `<pfx>PoolState` / `<pfx>WeatherLog` / `<pfx>AlmanacDate`… | 读写到别人的登记表，立绘/天气串档 |
| 父页 style id | `<pfx>-fs-hide` / `<pfx>-lock-floor-style` | 互相 display:none 对方的楼层 |
| 父页注入脚本 id | `<pfx>-lock-protect-script` | 清理函数互删 |
| window 标志位 | `__<pfx>Fullscreen` / `__<pfx>Cleanup` | 全屏状态互踩、原型恢复错乱 |
| console 前缀 | `[<pfx>]` | 排障时分不清谁打的日志 |
| 楼层 DOM 钩子 | 只依赖酒馆自身的 `.mes[mesid]`，不自己加全局 id | — |

**规则**：全项目搜一遍 `mirage`，出现一次就说明抄作业没改名——发给别人前必须清零。

## 2. 多前端并存检查单

装两个 gal 前端的酒馆里逐项确认：
1. 事件名、变量 key、id 全部不同前缀（上表）；
2. 各自的锁定前端只认自己的全屏楼层（靠 `mesid`，天然隔离）；
3. 聊天世界书条目名不同（`黄历_今日` 这类通用名要加前缀：`<pfx>_黄历_今日`）；
4. 两者的界面正则不要同时吃同一段文本（正则有顺序，各自 `findRegex` 范围要错开或只启用一个）。

## 3. 迭代发布流（每次改动都走这条线）

```
① 本地改代码 → npm run dev 裸跑自测（对应阶段的里程碑自测清单抽 2 条）
② 酒馆开 dev 正则（localhost，00 §0.4）真机回归：本阶段验收门 + 受影响的上一阶段验收门各抽 1 条
③ 构建（单文件内联，00 §0.5）
④ dist 产物入库提交
⑤ bump CDN 路径（新分支名/新 tag/新子目录——别等缓存过期，坑 29）
⑥ 正式界面正则 + 锁定前端脚本里的地址同步换
⑦ 真机终验一轮（发送→翻页→重roll→删楼→全屏，五分钟走完）
```

**约定**：①② 之前不许跳到 ③——未经真机验证的产物不发 CDN；⑥ 没做完不通知使用者更新。

## 4. 版本兼容意识

- 酒馆助手升级可能增删全局函数——所有全局调用保持 `typeof === 'function'` 判空降级（坑 18 的习惯化）。
- 本教程基于 2026-09 快照；升级后先在测试聊天里过一遍阶段三/四/五的验收门再更新到主力聊天。
- 每次大改在 SKILL 或项目 README 记一行"改了什么、哪条验收门重跑过"——交接时这就是全部事实。
