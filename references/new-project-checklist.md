# 新建项目决策清单（动手前先过这一份）

先做决定，再写代码。砍功能的判断在这一步做，不在写代码时做。每个决策都有推荐的保守默认值——拿不准就用默认值。

## 1. 开工三格

- **目标**：一句话说清新项目做成什么、给哪张卡用。
- **红线**：绝对不能碰的（如：不改动某现有项目、不联网上传隐私）。
- **验收**：怎么算做完——至少明确「本地浏览器可播放」与「真酒馆导入可播放」两道门各验什么。

向用户复述三格，对上了才开工。

## 2. 九个决策点

| # | 决策 | 选项（默认值加粗） | 影响 |
|---|---|---|---|
| D1 | 叙事形态 | **galgame 对话流** / 强分支多线 / 数值驱动模拟 | 决定协议规模：多线需要更多控制行与选项语义 |
| D2 | 图资产策略 | **无图（纯文字+氛围色）** / 静态查表（少量直链） / 人物池+地点池引擎 / 完整批量生图管线 | 图是最重的成本项，从最轻开始，留升级路径 |
| D3 | 音频策略 | **Web Audio 合成 SFX（零文件）** / +直链 BGM / 无声 | 合成 SFX 成本≈0，建议默认带上 |
| D4 | 变量策略 | **全 MVU（带降级）** / 轻量聊天变量（不用 MVU） / 无变量 | 变量是「AI 记得状态」的根；不上 MVU 就得自己设计变量协议 |
| D5 | 天气与昼夜 | **时段天气引擎（建议默认带）** / 仅昼夜二态（无天气） / 无时间流逝概念 | 昼夜/时段感几乎所有卡都需要；天气还联动地点池室外降权、场景扰动、AI 注入 |
| D6 | 多角色位置 | **不做（单角色/少量角色）** / 角色地点池（日程+空闲加权随机） | 常驻 NPC ≥ 4 个且「找人/偶遇」是玩法时才值得做 |
| D7 | 小手机 | **不做** / 最小壳（聊天+天气+设置） / 完整社交模拟（朋友圈/论坛/群聊） | 主线外角色社交 + 信息聚合面板；社交生成依赖副API |
| D8 | 世界书写入 | 无 / **状态快照条目（单条目幂等翻页）** / 业务条目（蓝绿灯增删） | 前端写世界书让 AI 每轮看到最新游戏状态 |
| D9 | 交付方式 | **正式交付（CI 或手动发布到 CDN）** / 仅本地 demo | 交付决定 JSON 清单与发布管线工作量 |

## 3. v1 最小可玩范围冻结

**必做**（缺一个就不成体系）：

1. 剧本协议 + 解析器（纯函数、可单测）
2. 事件层 + 楼层三态 + 生成锁
3. 播放层：打字机 + 立绘（可只有单张默认图）+ 背景（可纯色渐变）+ 选项面板
4. 发送 / 重生成链路

**建议带上**：MVU（含静默降级）——它决定「AI 是否记得状态」，后补要迁移数据，早搭便宜；**时段天气与昼夜**——自生成零数据成本，CG 变体/滤镜/地点降权/AI 注入都吃它的口径，早定省返工。

**明确延后**：随机池图引擎、音频、多角色位置池、小手机、世界书写入、锁定前端、批量生图管线、图鉴/地图/日历等大屏。v1 一律不做，接口留空即可。

## 4. 子系统启用时机（什么时候才值得做）

| 子系统 | 启用信号 |
|---|---|
| 时段天气引擎 | 游戏内时间会流逝（几乎总是成立）——v1 就带，哪怕视觉层只做昼夜滤镜 |
| 角色地点池 | 常驻有名 NPC ≥ 4 个，且「找人/偶遇/谁在哪」是玩法的一部分 |
| 小手机 | 需要主线外的角色社交（私聊/朋友圈/论坛）或统一信息聚合面板；社交生成需配副API |
| 随机池图引擎 | 同类实体（路人/NPC/地点）会超过 10 个，或逐个配图不可维护；需要「文图一致性」或「先抽后演」玩法 |
| 直链 BGM | 你手里确有可直连的音频文件 URL |
| 世界书状态快照 | 游戏有「当前状态」需要 AI 每轮看到（时间/地点/天气/关系值） |
| 世界书业务条目 | 有「档案型」对象随剧情累积（结案/解锁后转为省 token 的绿灯） |
| 批量生图管线 | 图片总量 ≥ 50 张，手写 URL 已经开始出错 |
| 锁定前端脚本 | 真机上切楼层/其他楼层干扰全屏体验已成实际问题 |
| 移动端适配 | 用户群里有手机玩家；至少先做「触摸翻页 + 手动 isMobile 开关」 |

## 5. 阶段推进与验收门

| 阶段 | 内容 | 完成标志（可验收） |
|---|---|---|
| A 协议+解析 | 定协议、写解析器纯函数 | mock 楼层文本喂入，ScriptLine[] 输出正确；无 `<content>` 时降级正确 |
| B 事件层 | GameContext 四信号 + 三态 + 生成锁 | 本地正则（disabled JSON 指向 localhost）下真酒馆翻楼/发送/重生成闭环 |
| C 演出层 | 打字机/立绘/背景/选项 | 浏览器裸跑可完整播一幕，交互不卡帧 |
| D 可选子系统 | 按 §4 逐个加 | 每个子系统各自有验收样例 |
| E 交付 | 交付 JSON + 发布 + 真酒馆导入 | 按导入说明五步走通，蓝灯条目出现、iframe 正常加载 |

规则：**跨阶段不加功能**。阶段内发现上一阶段设计错了，回到那一阶段改，不堆兼容补丁。

## 6. 命名与隔离约定（新项目必做）

- 所有 localStorage 键、window 标志位、自定义事件名、正则 JSON 的 `scriptName` 一律带 `<项目名>` 前缀（如 `<项目名>-sfx-settings`、`window.__<项目名>Fullscreen`、`<项目名>_story_updated`）——多个前端项目共存于同一酒馆时不互相污染。
- 世界书条目名前缀同理（如 `<项目名>_状态`）。
- 这些前缀在项目动工第一天定死，中途改名成本极高。
