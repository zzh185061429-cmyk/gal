# 美术资产管线（可选子系统）

图片资产（几十到几百张立绘/CG）不手写：**本地批量出图 → 图床上传 → 生成器脚本把 manifest 转成 `src/data/*.ts` → webpack 打包**。数据文件全部是生成产物，**勿手改**——改生成器再重跑。图片总量 < 50 张时不需要本管线，直接查表直链即可。

## 1. 批量生图（本地工具或脚本）

- 推荐工具：CG-Studio（零依赖本地批量生图工具，**独立项目、不随本 skill 分发**；`node server.mjs` 启动，只绑 127.0.0.1；迁移=拷走整个文件夹）。若工作区 `tools/CG-stuido/` 存在可直接用；没有就按下面的任务清单模式自建——任意「任务清单 + 断点续跑 + 图床 manifest 账本」管线等价。
- 两种模式：**地点 CG**（全局前缀 + 批量展开变体）与 **NPC 工坊**（批次设置 + 变体派生，参考图自动指向锚点保证同一人）。
- **任务清单模式**：每行 = 一张图（文件名 / 参考图 / 提示词）。
  - 参考图留空 = 文生图锚点；填另一行文件名 = 派生；填外部路径 = 导入已有图。
  - **预检**：拓扑排序标注 锚点/派生·第N批/参考缺失✗，循环依赖报错，上游失败下游连锁跳过。
  - **断点续跑**：manifest.json 记录每张图的完整来源与进度，重跑自动跳过已完成。

### 端点模式（防重复出图——最常踩的坑）

- **Chat API（默认，推荐）**：调 `/chat/completions` 让多模态模型回图。中转站不缓存 chat 响应，每次自然出不同图。
- **Images API**：调 `/images/generations` + `/images/edits`，需把防缓存词融入 prompt 正文（词池随机组合）。
- 「删图重跑还是同一张图」= Images API 请求被中转站缓存 → **切 Chat API 即解**。

### 图床上传

填图床 API Key（如 PostImages）→ 扫描可传文件 → 填图库映射 → 上传。Key 不落盘（每次重填）。完成在输出目录生成链接清单；已传的跳过；**逐张上传并把回执 URL 记入该目录 `manifest.json` 的 `uploads: { 文件名: { url } }`**——这份 manifest 就是生成器的数据源（账本）。

## 2. 生成器脚本（manifest → src/data/*.ts）

模式统一：读 manifest.json（图床账本）+ 结构描述 → 输出 TS 常量文件。

要点：

- **文件名规则即数据结构**：池子 `批次/编号/编号.png`（id 路径即属性 `B1_类别/男/老/富/01`）；变体 `NPC名-变体名.png`；地点场景 `场景路径去斜杠-变体.png`。命名规则定错，生成器全重写。
- 立绘情绪键用拼音（`kai-xin`/`mo-ren`），生成器里固定枚举顺序——前端 `EMOTION_MAP` 中文→拼音的映射要与生成器口径一致。
- 换图/加图的标准流程：生图 → 上传图床（manifest 记 URL）→ 跑对应生成器 → `pnpm build`。**永不动手编辑 src/data/*.ts 里的 URL。**

## 3. 变体成本规划

- 室内图只需 昼/夜 2 变体；室外 6 变体（晴阴雪×昼夜）——出图成本与变体数直接挂钩，**设计地点清单时就按这个口径规划**。
- 模板复用场景（无固定归属的场景，如荒庙/祠堂/井台）进 `TEMPLATE_LOCATIONS`，按路径末段名匹配——同一张图服务多个地点，省图量。

## 4. 与前端的衔接

- 背景CG：`getLocationImageSmart(路径,天气,昼夜)`（常驻精确→模板匹配）→ 地点池兜底（别名组/昼夜退化链）。
- 立绘：`CHARACTER_IMAGES[名].sprites[EMOTION_MAP[情绪]]` → 默认情绪兜底 → `dynamicSprites`（池引擎运行期登记）。
- 图库映射（上传面板）让生成器产出带语义的 TS 键名，前端只做查表。
