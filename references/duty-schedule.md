# 职守排班与事件预签（可选子系统）

解决的头号问题：**AI 不主动推进事件**——玩家不提案子，AI 就永远不送案源、委托、事件。根因是世界书里的触发描述全是被动句（"宫里来人宣旨""茶楼食客议论"），模型只顾眼前场景走阻力最小的路。正解不是把节奏句写硬，而是**前端把"今天该不该有事"算成确定性状态，以环境事实喂给 AI**。幻璃镜真机实现见其本体 skill `references/scheduling.md`；本篇是可移植的通用形制。

## 1. 设计公理

1. **前端定状态，AI 做叙事**：发不发事件由前端概率与排班决定，AI 只负责"怎么演"。
2. **只送事实不送指令**：状态行写"是夜天象有异"，不写"请安排一起案件"。祈使句在长对话里必然被惰性吞掉。
3. **去留归玩家**：触点是事实提示不是行动预设；状态条目零括号导演注、零替玩家安排的句子——括号注既是导演脚本又是越权代言，玩家最恨。
4. **确定性预签，不落盘**：同一日期同一义务永远同一结果（种子 = hash(日期+义务id)）。重读、重 roll、条目重建零漂移。现场掷骰 = 上午有案下午没案，自愈机制变自毁机制。
5. **有在办事件，义务全体虚设**：不投放新事件源。这条用机械虚设实现，文字节奏规则一条都不用写——案堆案与不发案两头都堵死。

## 2. 架构

```
月表（静态，义务名 + 日期锚点 + 各自概率）──→ 挂"每日翻页"的世界书条目
今日行（四态）：
  签中 → 义务句 + 事件钩子事实句
  未中 → 仅义务句
  有在办事件 → 虚设句（本该值夜，因有案在办，同僚代值）
  非排班日 → 整节省略（零 token）
```

- 排班锚点用日历：朔望（农历初一十五）、初几、节气日，全部本地查表可算。
- 翻页条目沿用幂等模式：日期键存聊天变量，跨日才重写；内容版本号升号让旧聊天自动归一。
- 与位置系统（character-locations.md）的分工：**一天一变的走条目，一刻一变的走生成时注入**。位置绝不写进翻页条目——条目会让角色全天钉死一处，且不知剧情现状。

## 3. 节令合流与日历锚定

- 排班义务撞上节庆是升级不是冲突：望日撞中秋，家宴自动从节名；岁末呈报升格为进历。
- 浮动节日公式（锚定日程用）：
  - 寒食 = 清明前一日（节气表取清明，公历减一天）；
  - 春社 / 秋社 = 立春 / 立秋后第五个**戊**日；入伏 = 夏至后第三个**庚**日——**戊庚是天干不是地支**，比对日干支的 gan 字段，查 zhi 永远不中；
  - 固定农历节日表里 `day: 0` = 当月最后一天（除夕），`day: 30` 小月回退廿九（地藏节式）。
- 若世界无星期概念（古代/架空），核心作息一律逐日节律，禁用 weekday 字段语义。

## 4. 身份边界纪律（配套世界书条目）

玩家角色的品级、身份、礼制边界必须在世界书里写死（如"正八品，无朝班，非奉召不面圣"），节庆例外单独列。不写，AI 会即兴提拔玩家上朝面圣——设计者与模型会犯同一种错。

## 5. 验收

- 引擎纯本地可测：种子复现、四态行、有案虚设、节令合流落点、浮动日公式（真年份抽查）。
- 真机才可验：AI 对事实钩子的编排手感、概率节奏体感、旧聊天版本自愈。
- 调参口收敛到一张义务表（概率/钩子句/代值句），玩着不对改表不动架构。
